## Development

**Local server:** `python -m http.server 8080` (or use `GregSweeper.bat` which opens the browser too).
No build step for the shipped app. Firebase SDK loaded via CDN. A root `package.json` exists for **dev/CI tooling ONLY** (the Playwright e2e harness + the `node --test` runner), the deployed app imports nothing from `node_modules` (ES modules + Firebase CDN), and `package.json` must never gain a runtime `dependencies` block. `npm install` is needed only to run the e2e suite locally; `node_modules` never deploys to GitHub Pages.

**Regression policy:** Every bug-fix PR adds (or extends) a test that FAILS before the fix and PASSES after, at the cheapest layer that can catch it: pure helper (`node --test`) > import-smoke > boot-smoke (e2e) > e2e journey. If the bug lived in DOM-coupled code, EXTRACT the decision into a pure helper and test that, the established pattern (`moltDay`, `resumeEligibility`, `scoreRowMatch`, and the Layer-1 helpers `winSubmissionPlan` / `parDisplayDecision` / `startupReconcilePlan` / `skillFeatDetection` / `weeklyAttemptSummary` / `gameoverPlan` / `modeRules` / `shareCard` / `statsForMode` / `remindCta`, plus pure exports inside DOM modules where extraction would be artificial: `headerRenderer.computeRemainingSafe`, `dailyHistoryChart.chartDateSlots`). DOM-coupled behavior that a pure helper can't reach is CALL-tested headless via the shared proxy shim `test/domShim.mjs` (cascadeGuard, powerUpPurity, persistRoundTrip). Name the incident in the test header and prefix the pinning case `REGRESSION:` (greppable). **Any e2e spec that measures GEOMETRY must call `settleAnimations(page)` (in `tests/e2e/helpers.mjs`) before every measurement**, the app animates the things those specs measure (the start-here label rides a 0.5s `fade-in-start` translating it -80% → -100% of its own height; revealed cells run their per-theme reveal choreography), so a rect sampled mid-flight reads a position the layout never settles at, and two samples taken at different animation phases disagree by an amount that depends only on machine load. That is what made `startHereLabel` / `wallResize` pass alone and fail in a full parallel run until 2026-07-18. The helper awaits every FINITE animation's `finished` promise plus one frame; infinite ones (theme particles, worm crawl) are skipped deliberately or it would hang. Fixing this class by widening a tolerance or adding a sleep is the wrong move, with the animations settled the offsets are exact, so `startHereLabel` now pins to a TENTH of a pixel where it used to need half a pixel and still flaked. A static `tsc --checkJs` gate (`npm run typecheck`, `jsconfig.json`) covers a curated set of pure `src/logic` modules, widen it as the heavy solver modules gain JSDoc. `.github/pull_request_template.md` carries this as a checklist. **Deferred:** Firebase rules ENFORCEMENT tests (emulator), the structure-assertion tests (`rules-contract.test.mjs` et al.) already catch the highest-frequency whitelist-drop class and the dedup/anti-cheat decisions are pinned in pure helpers, so the emulator (firebase-tools + Java in CI) waits until new `users/{uid}` fields start landing often.

**Deploy:** Push to `main` branch triggers GitHub Pages (via the `.github/workflows/deploy-pages.yml` Actions workflow, composes main at `/` and the `test` branch at `/test/`). Failed deploys SELF-HEAL: `.github/workflows/retry-pages-deploy.yml` fires on every failed deploy-pages run (GitHub's Pages backend has a recurring congestion window, observed 2026-07-04..06 ~15:00-16:30 UTC, where `actions/deploy-pages@v4` fails in ~10s with "Deployment failed, try again later." until a later re-dispatch, before the watchdog, a refit-dispatched deploy failing there left the new PAR_MODEL committed but undeployed until a human noticed), sleeps an escalating backoff sized by the consecutive-failure streak (10→60 min, 6 retries ≈ 3.75 h, then goes red + pings Discord, a fresh failure >3 h after the last starts a new cycle so an exhausted incident never eats the next day's retries), and re-dispatches deploy-pages on main. A re-dispatch rebuilds the artifact from the latest of BOTH branches, so a retry can never ship a stale main/test composition; it sleeps on ubuntu-latest (free on a public repo) so the single self-hosted runner is never held, and it skips whenever a newer deploy run is queued/running or the latest completed one succeeded (plus `concurrency: pages-retry, cancel-in-progress: true`, any newer deploy completion supersedes a sleeping retry). Decision logic is pure in `scripts/pages-deploy-retry.mjs`, pinned by `test/pagesDeployRetry.test.mjs` including the workflow-name coupling (a rename would silently disarm the watchdog). After push, bump `CACHE_NAME` in `sw.js` (format: `gregsweeper-v<MAJOR>.<MINOR>.<N>`). **The cache line tracks the app version** (aligned 2026-07-18, Christopher: the two had drifted to v1.9 app / v1.6.158 cache, which read as a bug): `CACHE_NAME`'s `MAJOR.MINOR` must always equal `CURRENT_VERSION` in `main.js`, and `N` is the per-deploy counter that resets to 0 on a version bump. So routine deploys on v1.9 go `gregsweeper-v1.9.0` → `v1.9.1` → `v1.9.2`, and the next release bumps `CURRENT_VERSION` to `v1.10` with `CACHE_NAME` restarting at `gregsweeper-v1.10.0`. Minor versions keep counting past 9 (1.10, 1.11, …); there is no 2.0 planned.

**A MINOR bump is a player-facing release, not a deploy counter** (his ruling 2026-07-18, holding the v1.10 bump: "people aren't going to care very much about the model like me"). Bump `CURRENT_VERSION` only when something has shipped that a player would care about, a mode, a modifier, a mechanic they can feel. Model and instrumentation work (new studies, refit changes, targeting logic) is real work and belongs in the Journal, but it does not headline a release. Two consequences: infrastructure-only stretches ride the `N` counter for as long as they need, and because the What's New NEW badge fires on any `CURRENT_VERSION` change, every bump must land with a What's New entry worth the interruption. Production serves at the **`gregsweeper.com`** custom domain (GitHub Pages custom domain; apex + `www` DNS via Porkbun's Cloudflare-backed ALIAS → `christopherwells.github.io`, HTTPS auto-provisioned by GitHub). The `test` branch deploys to `https://gregsweeper.com/test/` with an orange "TEST BUILD" banner and skips Firebase writes via `isTestEnvironment()`.
