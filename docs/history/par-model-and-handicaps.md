## Greg-par Model (Daily)
Daily par is a **log-linear (multiplicative) regression** over board features (`PAR_MODEL` carries `scale: 'log'`): `par = exp(intercept + Σ coef·feature)`, the lognormal MEDIAN, so par is always positive (no more negative-intercept-on-tiny-boards bug) and each coefficient is a **log-multiplier**, NOT seconds. Fit in R offline against real completion data. Coefficients are in `PAR_MODEL` in `src/logic/difficulty.js`; `predictPar` branches on `model.scale` (absent ⇒ the legacy additive-seconds form). The whole model is in `src/logic/dailyFeatures.js` (`computeDailyFeatures`, `predictPar`, `breakdownPar`, `applyParModel`). (Migrated from additive seconds → log 2026-07-02, v1.6.127; the player handicap became a multiplicative ratio in the same change, see Handicaps.)
- **Move type, not move count, is the primary signal.** The solver in `boardSolver.js` classifies every deduction into one of five buckets at the three `totalClicks++` sites: `passAMoves` (trivial propagation), `canonicalSubsetMoves` (Pass B subset with larger-constraint size ≤3, 1-1 / 1-2 / 1-1-1 shapes), `genericSubsetMoves` (Pass B, size ≥4), `advancedLogicMoves` (Pass C tank/gauss), `disjunctiveMoves` (Pass C with liar). Invariant: `passA + canonical + generic + advanced + disjunctive + 1 === totalClicks` for solvable boards. The solver still classifies all five, but the **model pools them for identifiability** (2026-06-08 rework): a VIF/sparsity audit showed the four raw move-types are too sparse / small-count to fit separately, so `predictPar` uses two earned tiers, **pattern** (`canonicalSubsetMoves + genericSubsetMoves`, subset deductions) and **search** (`advancedLogicMoves`, tank/gauss enumeration). `passAMoves` is dropped as a model predictor (it's a board-size proxy, VIF 7.4, absorbed into `cellCount`); `disjunctiveMoves` stays unmodeled (dropped 2026-05-04, confounded with `liarCellCount`). The solver keeps counting all five for diagnostics.
- **Stored feature vector (`dailyMeta`):** raw move-type counts + board dimensions (rows, cols, cellCount, totalMines, wallEdgeCount, etc.) + gimmick cell counts, UNCHANGED by the rework, so every historical board stays usable with no migration. The **model predictors are DERIVED from these** at predict/fit time: `cellCount` (lone size axis), `totalMines` (raw, VIF 3.6, fine once the redundant size features are dropped; density was tried 2026-06-08 but made the coefficient unreadable), `patternMoves`, `searchMoves`, `wallEdgeCount`, `zeroClusterCount`, and the modifier cell counts (kept split, sparse, prior-anchored until coverage missions build data). `nonZeroSafeCellCount` is dropped (near-redundant, VIF 23.7). One source of truth: `COEF_TERMS` in `dailyFeatures.js`, where each term is a function of the raw features (so the R refit derives the same from stored `dailyMeta`).
- **End-of-game modal** renders a per-term breakdown below par: `+18s search moves · +12s pattern moves · …`. Under the log model `breakdownPar` allocates the above-baseline seconds by each term's share of the log-difficulty (`coef·x / Σ coef·x`), so the chips still read in seconds and sum to par. Baseline terms (`exp(intercept + size)`) merge into a single chip to keep the line readable.
- **R refit workflow:** export Firebase JSON from the console → run `scripts/fit-par-model.qmd` → paste the emitted `PAR_MODEL = { ... }` block into `difficulty.js` → commit + deploy. The .qmd also runs diagnostics (residual plots, QQ for log-linear check, VIF for collinearity, bootstrap CIs).
- **Pre-ship scale anchor:** `scripts/calibrate-today.mjs` regenerates today's daily board locally and verifies `predictPar` lands inside the observed completion-time range before shipping new coefficients. One-board check, not a fit.
- **The board's shape gets its OWN par equation, composed from the square fit (per-shape equations, 2026-08-01, superseding the 2026-07-23 intercept offsets).** Christopher's ruling: "we might just want different par equations for each shape... priors can be informed by the square tilings." `PAR_MODEL_SHAPES` (refit-owned, between `PAR_MODEL_SHAPES:START/END` markers in difficulty.js) carries one FULL coefficient set per tiling, keyed by the exact `TILING_TYPES` strings; `modelFor(features)` in dailyFeatures.js dispatches, `modeTimed` wins first (quick play is rectangles-only), then `tilingType` selects its shape block, then `PAR_MODEL` for rectangles AND as the silent fallback for an unknown type (the same hazard `buildTiling`'s fallback carries: a typo prices as a rectangle with no error anywhere, so outside-code types must validate against `TILING_TYPES`; the `'6.6.6'` deep-link alias is normalized by `modelFor` and is never a block key). `predictPar` and `breakdownPar`'s default both resolve through it, so a tiling daily's win-modal numbers are automatically its shape's own equation with no caller edits. **The fit stays ONE joint brms model, not six:** the base formula is unchanged, and each shape contributes its 0/1 indicator (the old intercept offset relocated as that shape's intercept deviation) plus one `shape<S>_x_<F>` interaction per base feature, a SIGNED deviation of that feature's log-multiplier from the square's, every column under the same per-column zero-variance gate as `archivePlay`/`wormLoad` (an interaction is nonzero only on its shape's rows, so with no tiling rows the whole layer collapses and the fit is exactly the pre-shape fit). One fit because the player random intercept `(1|uid)` must be estimated jointly, or six per-shape fits would ship six disagreeing handicaps. **"Priors informed by the square" was UPGRADED to "priors informed by the lab" (2026-08-03, his four seeding rulings after the Par Lab prior fit):** the 18 CORE deviations (intercept, per-cell, per-mine × 6 shapes) now center on the Par Lab posteriors at DOUBLED lab width, `normal(lab mean, 2 × lab sd)`, loaded from the frozen `scripts/data/parlab-prior-centers.json` (terms with ≥ `LAB_SEED_MIN_ROWS` (5) lab rows; the n=1 gimmick-by-shape cells stay `normal(0, INTERACTION_PRIOR_SD = 0.5)` per his observations-not-conclusions ruling, and so does any unseeded term). Signed either way, because a lattice can make a feature cheaper, hex composes to a NEGATIVE per-cell coefficient, which is expected and handled (breakdownPar folds baseline-flagged terms into one exp() chip, so no negative chip can render). **Sampling geometry is TWO-PATH (2026-08-01, fixing the same-day incident):** #203's first cut removed the class-wide `lb = 0` blanket from `build_priors` so the signed deviations could share class b, betting positivity on the lognormals' own support plus a custom init, and the first dispatched run was REJECTED (divergent 14/4000 against a gate of 10, 2950/4000 max-treedepth exceedances, min ESS 464) on the SAME data the bounded setup had fit cleanly twelve hours earlier (Rhat 1.007, ESS 1060, 0 divergent). The bound is a TRANSFORM statement and support only a density one: with `lb = 0` Stan samples class b through a log transform, without it the positive-support lognormal is a hard wall at zero in the sampled space (several OLS-seeded medians sit at ~0.001, pressed against it), exactly divergences + treedepth blowup, and the init (`make_positive_init`, now GONE) only patched initialization, never geometry. So the fit selects on ONE boolean where the formula is built: with NO active deviation column (every night until tiling scores exist) it is the flat formula with the blanket restored, bit-identical in specification to pre-#203; with active columns it becomes a brms non-linear split, `bf(log(pure_time) ~ base + dev, nl = TRUE)`, where each nlpar gets its OWN class b (the sanctioned way to bound one group of fixed effects and not another): `base` (intercept, base features, `(1|uid)`) keeps the lognormals under a `nlpar = "base"` blanket, `dev` (`0 +` the active columns) carries the signed normals unbounded. Both paths flow into the same extraction through `flat_fixef`/`flat_ranef_uid`, which strip the nl path's `base_`/`dev_` name prefixes back to the flat names, so the split is a formula-construction detail, not two pipelines. The timed fit keeps its own blanket; the digit fit (no signed terms anywhere) is always flat and gets its blanket back through `build_priors`' flat path. **The ship guard, and the LAB-SEED property (replacing the launch PARITY property on 2026-08-03):** each emitted shape block = final shipped base + deviations, where a LAB-SEEDED core term ships its fitted posterior whenever its column entered the fit (no 20-row wait, the guard exists to stop bare prior medians, and a lab center is 86 boards of designed data) and its lab CENTER when no live rows exist at all (the zero-variance gate keeps the column out of the formula, so there is no posterior to read); UNSEEDED terms keep the full `NEW_FEATURE_DATA_THRESHOLD` (20) earn guard. So the shipped blocks price the lattices from day one, seeded 2026-08-03 by `scripts/seed-par-model-shapes.R` through the nightly's own EMITTER region, daily-config multipliers hex 1.02 / 4.8.8 1.20 / rhombille 1.77 / cairo 2.03 / floret 2.77 / deltoidal 5.14, and rectangles still price byte-identically on `PAR_MODEL`. The contract test now pins block-minus-base against the frozen lab JSON (seeded terms within emission rounding, unseeded coefficients exactly), so difficulty.js and the lab artifact cannot drift apart silently; the lab-priors loader in the refit fails SOFT (missing file → zero-centered deviations) precisely because that test then fails LOUD on the refit's own commit. This only affects tiling boards, which production cannot build while the rotation is dark, `?coastline=`/parLab practice pars on test builds got honest overnight, and nothing else moved. The measured WHY behind per-shape-never-pooled is unchanged: a honeycomb certifies at techniqueLevel 0 on 95-99% of boards and produced ZERO tier-2 boards at any density, while 4.8.8 spans the full range much as a rectangle does (33/40/27 across tiers 0/1/2 at density 0.20), the reasoning tiers carry most of a shape's difficulty on their own, so a whole per-shape model fit independently would ship its priors back looking like a fit, and the deviation parameterization is what lets each shape's equation EXIST without ever being fit from nothing. Rhombille has NO Pass B at all while 62% of deltoidal boards reach tier 2; Pass B's substrate (adjacent-pair neighbor overlap caps at 2 on both Archimedean tilings against 4 on a rectangle, mean shared 2.86 rect / 1.91 4.8.8 / 1.88 hex; mean adjacent valence gap 2.34 on 4.8.8 vs 0.80 rect / 0.54 hex) is the standing evidence the shapes differ from each other as much as from the square, which is why deviations are per-shape, never pooled "tiling" terms. Fitted deviations ride modelHistory rows as the additive `shapeDeviations` field ({mean, sd} per fit term), NEVER `target_candidates` (a deviation is not force-injectable, and the Journal reads `candidates` only, so no Journal change). **The digit frame went rectangles-only in the same change:** at fixed density the digit shares differ BY LATTICE (rhombille's 5plus share 4.4× the 4.8.8's, 15× the hex's), so tiling rows would turn the digit coefficients into part-shape indicators the pairwise decorrelation machinery cannot see; the cost, digit data at half speed under a 50/50 rotation, is accepted until the shape confound gets a design of its own. R-side pricing stays ONE equation mirroring the FIT: `apply_par_model` takes a `shape_devs` list (indicator + interaction terms added to the linear predictor, algebraically identical to applying the composed block to that shape's rows), and the outlier screen / residual fallback recover the SHIPPED deviations by differencing `PAR_MODEL_SHAPES` against `PAR_MODEL` (`parse_par_model_shapes_devs`), so a tiling row is always screened against the equation it actually shipped under.
- **`tilingType` is DERIVED from the board and ABSENT on rectangles.** `computeDailyFeatures` reads `board._tiling.type`; it is not stamped by the caller the way `features.modeTimed` is, because a daily board's features are recomputed independently by every client, by `daily-board-pipeline.mjs`, and by the nightly `verify-canonical-boards.mjs`, a caller-stamped shape could differ between them and a derived one cannot. It must stay ABSENT (never `'rect'`, never `0`) on a rectangular board: the verify sweep's vintage escape hatch is `stored === undefined && recomputed === 0`, so a new key recomputing to a truthy value would hard-fail every historical date. Since 2026-08-01 nothing derives indicator TERMS from it at all, `modelFor` uses it to SELECT the model, so it still never reaches `dailyMeta` as anything but itself. A new tiling type is a new VALUE of an existing key, never a new key, which is why `FEATURES_EPOCH` does not move when one lands and why `SOLVER_DERIVED_FEATURE_KEYS` stays as it is. Pinned in `test/tilingFeatures.test.mjs` + `test/tilingParModelContract.test.mjs`. **The two hand-maintained `sprintf` templates that used to emit `PAR_MODEL` and `PAR_MODEL_TIMED` are GONE**, their slot/arg counts silently drifted twice, each drift shifting every later coefficient one slot. ## Par Bands (daily/weekly difficulty distribution)

**Christopher's ruling (2026-08-02): every daily lands at par between 20s and 240s, every weekly between 60s and 360s, each distribution "skewed lightly toward the easy end, occasional hard boards."** Before this, difficulty was incidental, whatever the mission lottery picked (past dailies: p50 79s, 5% above 180s; the weekly hardest-stack-wins argmax shipped p50 121s with a 251s tail). The shape is the **"hard-day coin,"** his pick from a rendered three-way comparison (vs a single scaled Beta and a log-uniform): 85% of days draw an easy target from Beta(2,5), 15% flip hard and draw from Beta(2,2) on the upper span. The ceilings were raised 180→240 / 300→360 in the same conversation with the easy hill **kept anchored where he approved it**, so the bands keep the original geometry as `easyHi`/`hardLo`: daily easy on [20,180] / hard on [108,240], weekly easy on [60,300] / hard on [192,360].

- **One source: `src/logic/parBand.js`** (leaf, imports only seededRandom; in the typecheck set and the sw.js precache, the swPrecache gate catches a statically-imported module missing from ASSETS). Bands, `HARD_DAY_PROB` (0.15), `PAR_KERNEL_SIGMA` (0.35), the target draw, the kernel/clamp, and the weekly `bandedArgmax` all live here, consumed by BOTH sides of both mirror pairs.
- **The draw** (`drawDailyTargetPar`/`drawWeeklyTargetPar`): deterministic from the date string alone (the `resolveDailyShape` pattern, no fetched file to desync on). Namespaces `${date}:parTarget` / `${weekStart}:weeklyParTarget` are distinct BECAUSE a weekStart is itself a Monday date string, sharing one would correlate every Monday daily with its week's weekly. Exactly two rng() calls per draw (regime coin, position). The Beta inverses bisect closed-form polynomial CDFs (integer Beta parameters, no `Math.pow`), bit-identical on every engine; `Math.exp/log` appear only in the kernel, the same functions `predictPar` already uses upstream, so no new cross-engine divergence class.
- **Daily composition** (`selectMissionWinner(entries, dateString, bandCtx)`): candidates carry `par = predictPar(features)` (both `selectDailyRngSeed.js` and `daily-board-pipeline.mjs`, features were already computed; par is one call). Inside the existing lottery, each non-decorrelation score is multiplied by its band weight: 0 outside the band, the log-scale closeness kernel inside (1.42× off keeps ~61%, 2× ~14%, 3× <1%). Composition rules, all pinned in `test/missionWinner.test.mjs`: **decorrelation supremacy is checked on RAW scores** and a decorrelation winner is exempt from the band (its R-derived weight is calibrated against exactly that contest; those rare days chase a residual corner); an **all-zero-score pool draws ∝ band weight** (replaces the old uniform draw, no mission signal, so the band alone settles it); a **par-less pool disengages** to the legacy draw verbatim; an **all-out-of-band pool** falls back to the unclamped kernel (nearest-in-log wins rather than undefined). Every branch consumes exactly ONE rng() from the same `:missionDraw` stream, so banded and pre-band clients stay stream-compatible.
- **Weekly composition**: `selectWeeklyRngSeed.js` computes features + par per candidate and picks via `bandedArgmax`, (gimmick count + advancedLogicMoves×0.01) × band weight, ties to the earlier slot; the 2-4 modifier stack stays forced (measured: average stack 3.0 → 2.6-2.9). **The weekly selection rule is now ONE copy**: `precompute-weekly-board.mjs` calls `selectWeeklyRngSeed` and rebuilds the winner through its existing retry loop, replacing the private contest copy it had (the weekly half of the mirror-pair drift class the daily slot arithmetic already demonstrated; the no-solvable-candidate fallback, bare weekStart seed, is what the selector returns in that case, so the fallback shape is unchanged).
- **Honest limits, measured before shipping** (40 future daily contests + 16 weekly replayed): selection can only pick what generation offers, pools top out ~100-140s most days (≥180s on ~8/40 dates), so a hard target above ~170s usually ships the pool's hardest in-band board; **extra hard-reach candidate slots were offered and deliberately deferred** (his call, 2026-08-02: ship the band, measure the feel first). Mission-win shares shift ≤ ~4 points under the kernel (worm 34%→30%), so the experiment keeps steering which modifier a board studies while the band steers how long it runs.

## Handicaps (user-specific par offsets)
- Each user has a handicap as a **MULTIPLICATIVE RATIO `k`**, their typical `time / par` vs Greg's CLEAN par across recent dailies. `k > 1` = typically slower than Greg, `k < 1` = faster/better. `personalPar = par × k + bombSeconds`: clean skill scales with the board (the ratio), the player's typical bomb cost is a SEPARATE additive-seconds term. The RATING shown to players is `(1−k)×refPar` seconds and `(1−k)×100`%, **positive = faster/better than Greg** (opposite sign from the Lab File "your pace" line, which is a par composition `gregPar×(k−1)` that must sum to personal par).
- Stored in `src/logic/handicaps.json`, a static JSON asset committed to the repo. Keyed by Firebase anonymous uid. Not in Firebase, shipping via a static file sidesteps write-permission issues, and handicaps then update the same way everything else does (commit → GitHub Pages redeploy).
- Computed server-side (GitHub-Actions-side) by `scripts/refit-par-model.R` running daily: fits `brm(log(pure_time) ~ features + (1|uid))` where `pure_time` has ALL bomb cost removed BEFORE logging (so there is no bomb regressor). The ratio is `k = exp(recentered random intercept)` (geometric-mean recentering → play-weighted geometric mean of `k` is 1), clamped to a WIDE `[0.1, 10]` sanity bound, partial pooling is the real regularizer; the clamp only rejects garbage, never a well-sampled player. Each player's mean per-play bomb cost is a SEPARATE `bombSeconds`. Falls back to a residuals path (geometric-mean ratio + bombSeconds) when N or n_players is below the fit threshold.
- **`handicaps.json` is `format: "logratio-v1"`**: `handicaps {uid: k}`, `handicapDetails {uid: {k, bombSeconds}}`, top-level `refPar` (median day-of par, for the seconds display), `secPerBombHit`. Static JSON committed to the repo (ships via GitHub Pages redeploy).
- Client reads via `src/logic/handicaps.js`: `loadHandicaps()` fetches once; `getHandicapRatio(uid)` returns `k` (default 1 = neutral/unrated); `ratioDisplaySeconds`/`ratioDisplayPercent` + `getHandicapSeconds`/`getHandicapPercent` give the RATING display; `personalPar(par, uid) = par × k + bombSeconds`; `getHandicapsMeta()` returns `{updatedAt, modelFitN, nPlayers, method, format, refPar, secPerBombHit}`. A dual-reader treats a legacy additive file (no `format` tag) as unrated (`k=1`) so additive seconds are never misread as ratios. Used in the end-of-game modal ("Your par" vs "Greg's Time"), the Adjusted leaderboard, and diagnostics.
