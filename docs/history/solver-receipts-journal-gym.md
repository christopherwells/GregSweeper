## Board Solver Architecture

Two-layer solver guarantees no 50/50 guesses:

1. **Board solver** (`boardSolver.js`): Simulates full game playthrough from first click. Wall-aware neighbor lists. Gimmick handling via `getPlayerVisibleCount`:
   - **Mystery / sonar / compass / wormhole:** return UNKNOWN (no direct per-cell constraint; sonar/compass/wormhole contribute separate gimmick-range constraints in Pass A/B/C, reveal-gated on `board._gatedCert` boards, see the No-Guess Contract section). Liar-stacked gimmick cells contribute NO range constraint (their displayed value already includes the lie).
   - **Liar:** return UNKNOWN. Liar's displayed value is true count ±1, a disjunctive constraint, not a single value. `buildLiarConstraints` emits `{allowedMines: [X-1, X+1]}` for Pass C tank solver.
   - **Mirror:** return `cell.adjacentMines` (the true count). The displayed value shows the partner's count for visual deception; a smart player who recognizes the pair can mentally un-swap. Using `displayedMines` would create false constraints that made post-gimmick boards spuriously unsolvable.
   - Returns `{ solvable, remainingUnknowns, totalClicks, techniqueLevel }` where `techniqueLevel` is 0 (Pass A), 1 (Pass B subset), 2 (Pass C tank/gauss), or 3 (required disjunctive liar reasoning).

2. **Constraint solver** (`constraintSolver.js`): Union-find partitions independent constraint groups. Constraints use `allowedMines: number[]`, single-element for exact, multi-element for disjunctive (liar), plus an optional `origin` (the source cell index) for provenance. Tank solver (bitmask brute-force with disjunctive check) for <=20 unknowns; Gaussian elimination for larger groups (exact constraints only, disjunctive filtered out before gauss). Gauss is sound-or-skip (reworked 2026-06-10): float row-reduction with partial pivoting, then a row yields deductions ONLY if every coefficient and the RHS snap to integers within 1e-6, extracted via the binary-variable bound rule (rhs == min/max achievable). The old extraction `Math.round`ed coefficients before pattern-matching, 0/1 systems legitimately produce 0.5 entries under elimination, and on unsatisfiable systems (wrong player flag) it fabricated "provable mine" verdicts (`test/gaussSoundness.test.mjs` pins both the fabrication case and a witness-consistency sweep). Gauss remains INCOMPLETE by design, a missed deduction is honest, a false one never is. `solveConstraints` returns, besides the flat `mines`/`safe` sets: `groups` (per-component `{unknowns, hasDisjunctive, origins}`), `cellGroup` (cell → group index for every solved cell), and `contradiction` (a tank component with zero satisfying assignments, on live player state this means a provably wrong flag).

**Deduction substrate (2026-06-10)**, the engine-as-witness layer the receipt surfaces consume:
- **Trace**: `isBoardSolvable(..., { trace: true })` returns `result.trace = [{cell, tier, sources}]`, one entry per deduced reveal, where `sources` are the origin cells of the constraints that PROVED it (Pass A: the one constraint; Pass B: the subset pair; Pass C: the whole union-find component, the honest minimal explanation for enumeration). Collection-only: counters, ordering, and behavior are unchanged; generation hot loops don't pass the flag. Invariant: `trace.length + 1 === totalClicks`.
- **Per-group disjunctive attribution**: a Pass C deduction counts as `disjunctiveMoves` (and promotes techniqueLevel to 3) only if ITS union-find component carries a liar constraint. The old version batch-flagged every Pass C deduction of a round whenever any liar constraint existed anywhere, inflating `disjunctiveMoves` in dailyMeta on liar boards and over-promoting techniqueLevel. Consequence: on liar boards, `advancedLogicMoves` (the model's searchMoves) can be higher and `disjunctiveMoves` lower than under the old counting, the honest direction; historical dailyMeta rows written by old clients carry the old counting.
- **`findDeducibleFrontier(board, {respectFlags})`**: everything provable from the live state, full safe + mine frontier, each with `{tier, sources}`, plus `contradiction`. `respectFlags: false` runs flags-blind: player flags are CLAIMS, not facts, and one wrong flag can poison the constraint system into certifying a mine "provably safe", every player-facing verdict must use the flags-blind run. `findNextSafeMove` is now a thin first-safe-cell wrapper over it.
- **`detectWrongFlags(board)`**: dual-solve diff, a player flag is provably wrong when the flags-blind run proves that cell safe; the flags-respecting run's `contradiction` additionally says "some flag is wrong" without localizing it.
- **Click timeline**: `state.clickTimeline = [{t, r, c, a}]` (a = r/f/u/c) records every player action via `recordPlayerAction` in gameState.js, reset per game, persisted with the auto-save, capped at 2000. The ground truth for player-grounded receipt claims (never narrate the solver's order as the player's).

The **admission predicate IS the curriculum**: `accepts(r)` is the bucket gate over the `isBoardSolvable` result; named-shape lessons add `requiresPattern` ('1-1' / '1-2' / 'hole' / 'triangle' / '1-2-1' / '1-2-2-1' / '1-3-1' / '2-2-2'), which `generateLessonBoard` verifies via `lessonRequiresShape` for the 7 STRICT shapes (`requireShape: true`) or `lessonShowsPattern` for the 2 RECOGNITION composites (1-2-1 / 1-2-2-1, `requireShape: false`, they CANNOT be forced, see below). Both read the shared `patternNames` detector the coaching and receipts use, so a lesson can never teach a shape the rest of the game cannot name. (`lessonShowsPattern`, the lighter "appears on a path" check, remains as a tested utility but is no longer the gate for any lesson.) **`lessonShowsPattern` models REAL PLAY, one reveal at a time, not a frontier wave**: it snapshots the reveal state, then repeatedly checks whether the target shape is the top read of any provable cell and, if not, makes a SINGLE flood-click and looks again (restoring the board after). One-at-a-time matters two ways: (1) triangles and 2-2-2 corners form mid-solve, not at the opening (triangles measured 0% at the opening), so an opening-only check missed them; (2) holes/triangles are TRANSIENT, the boxed pocket dissolves into a plain 1-1 the instant the wider clue's other neighbor is revealed, so a wave check (classify the whole frontier at its peak) admits boards a one-at-a-time player can never perform the shape on. Measured: under a wave check triangles surfaced ~100% but only ~80% of real one-at-a-time play, and 2-2-2 corners ~67%, a "2-2-2 corner" lesson the player could finish a third of the time without ever performing a 2-2-2, breaking the gym's premise (named only after you perform it). The one-at-a-time gate lifts engaged-play performance to 20/20 for every named-shape lesson while keeping yields healthy. **The 7 strict shapes REQUIRE the shape (`lessonRequiresShape`), rebuilt 2026-06-16 on a SOUND substrate** (`minimalProof.js` + `proofClassify.js`): the gate plays FLAGS-AWARE and, for each provable cell, asks `simplestGatingRank` for the CHEAPEST shape that PROVABLY forces it (every rank gated by `subsetForces`, the cited clues must force the square across all satisfying assignments). It flags/reveals every cell solvable by something SIMPLER than the lesson's shape (rank < the shape's curriculum rank) and admits the board only if that play STALLS with a shape-rank cell still required → the technique is unavoidable. This replaced the old flags-BLIND gate, which mistook a flag-then-count cell for a forced subset read and so admitted boards solvable by pure counting (Christopher's report: holes / triangles / 1-2-1 / 1-2-2-1 / 2-2-2 all leaked counting-solvable boards). **1-2-1 and 1-2-2-1 are RECOGNITION lessons, not forced ones, proven IMPOSSIBLE to force (2026-06-16):** a 1-2-1 ALWAYS decomposes, its two outer mines are each a plain 1-2 (the 1 ⊂ the 2, rank 2 < the 1-2-1's rank 5), so a flagging player flags those and the middle COUNTS out; `lessonRequiresShape` correctly returns false for every 1-2-1 board. It IS a pair of 1-2s and cannot be required the way an ambiguous-pocket hole or a forced-corner 1-3-1 can. So those two use `lessonShowsPattern` + an accepts gate demanding real subset reasoning (`techniqueLevel >= 1`, not pure counting) on normal boards (fast, ~6-90ms); the player recognizes the shape and the coaching names it. The other 7 shapes have a genuinely irreducible deduction (ambiguous pocket / forced corner mine / no cheaper proof) and are force-required. **The 1-2 lesson was the hard case and exposed a real classifier bug**: evaluated soundly, 1-2 was 0%-required (1-1 was 97%). Two reasons. (a) `classifyPattern` named pairs from the frontier's ATTRIBUTED sources, which shadow a 1-2's freed square to "1-1," so '1-2' almost never surfaced. (b) the textbook 1-2's headline payload is a forced MINE (the square only the 2 sees), and the gym never requires flagging (you finish by revealing safes; the gate is flags-blind, so a flag never unlocks anything), so a mine-find can't be "required." The fix recognizes the 1-2 by its OVERLAP geometry (`matchesOverlapPair`), which finds the forced-SAFE square the lesson's own rule already describes, "the square only the smaller number sees is safe." That safe square IS requirable, exactly like 1-1, so 1-2 went 0% → 100%. `matchesOverlapPair` (two plain clues sharing hidden squares; when `valBig - valSmall === |bigClue's exclusive|`, the small clue's exclusive squares are all safe and the big clue's exclusive all mine; 1-1 is the equal-value subset case) replaced the shadow-prone source-based pair naming in `classifyPattern`, which also fixes how 1-2s are named in coaching and receipts. `countingBasics` = `techniqueLevel === 0 && passAMoves >= 3`; `subset11` / `subset12` share the canonical-subset bucket gate (tier 1, nothing harder) and are split by `requiresPattern` '1-1' vs '1-2' (the bucket counts can't tell a 1-1 from a 1-2; the classifier reads the two clue digits); `holes` / `triangles` = solvable, `techniqueLevel <= 1`, no advanced logic, with the boxed-pocket shape on the path (a clue boxed to exactly 2 hidden cells, a hole, or exactly 3, a triangle, sitting inside a wider ≥4-hidden clue that shares the whole pocket, so the wider clue's extra cells are forced; it is a generic subset given a shape name); `oneTwoOne` / `oneTwoTwoOne` / `oneThreeOneCorner` / `twoTwoTwoCorner` = solvable, no liar, `techniqueLevel <= 2`, shape on the path (`oneThreeOneCorner` = a 3 at an L bend with a 1 on each arm sees five squares; the two 1s cap four of them at one mine each, forcing the third mine into the square only the 3 sees, leaving each 1's far square safe, a modified 1-2; `twoTwoTwoCorner` = the hardest, a tier-2 multi-clue read: a central 2 adjacent to the safe target whose OTHER hidden cells split into two disjoint groups, each lower-bounded to ≥1 mine by a flanking 2, the two groups use up the central 2's whole count, so the square only the central 2 sees is safe). `lessonRequiresShape` reveals by FLOODING zeros (like a real click), so a revealed 0-clue never sits with hidden neighbors, that impossible state otherwise confuses the recognizers. Measured generation time (2026-06-16, the rebuilt gate; median over varied seeds): holes ~270ms, triangles ~380ms, oneThreeOneCorner ~120ms, twoTwoTwoCorner ~630ms (the dearest strict), oneTwoOne ~6ms, oneTwoTwoOne ~88ms (recognition composites are near-instant on normal boards); worst-case seed ~1-2.3s, and NOTHING fails to generate, live, no pre-baked content. A one-time per-board cost behind the lesson-load; add a spinner or tune board size if a strict corner ever feels slow. The flags-aware gate flags only AVOIDABLE mines (rank cheaper than the shape), so a shape's OWN forced mine, the 1-3-1 corner, the 1-2-1's outer 1-2s, stays unflagged and its recognizer still sees it (the old gate's pocket-family-only flagging hack is gone). Per-lesson `attempts` budgets cover the lower strict yields. Verified end-to-end in `test/lexicon.test.mjs` (the 6 strict lessons REQUIRE their shape, the 2 recognition composites SHOW theirs + need subset reasoning, all 9 generate and stay completable through provably-safe clicks alone), with the underlying classifier soundness swept against a brute-force oracle in `test/proofClassify.test.mjs` (0 violations over ~14K named cells). **Hard gate (added after triangles once shipped wired-but-non-generating at 0/4000, count-based shape detection was shadowed by the frontier attributing each cell to its first/smallest subset):** every lesson must measure >0 yield BEFORE it ships. Tested invariant: every lesson is completable through provably-safe clicks alone (the gate can never soft-lock). **Gym entry:** the `#mode-card-gym` card has the `.mode-card` class for the title grid but NO `data-mode`; the generic mode-card handler in main.js guards `if (!mode) return` so it can't fall through to `switchMode(undefined)` (which started a hidden challenge game under the gym overlay, fixed 2026-06-15).
  - **Shared pattern detector** (`src/logic/patternNames.js`, pure, node-tested in `test/patternNames.test.mjs`): `classifyPattern(board, ded, {rows, cols, neighborCache?}) -> {name, family}` over a `{row, col, tier, sources, kind}` frontier/trace entry. Names: `1-1 | 1-2 | 1-2-1 | 1-2-2-1 | 1-3-1 | hole | triangle | 2-2-2 | flag-reduction | pair` (tier-1 non-canonical, e.g. 2-3) `| region` (tier-2/3 enumeration, deliberately unnamed) `| count` (tier-0). **Geometry, not tier:** the SAME visual 1-2-1 resolves at tier 1 or tier 2 depending on flanking clues (a flanking 1-1 subset gives a tier-1 path), so the named shapes are recognized by board scans, never by the move-type buckets (which only say "the larger constraint had ≤3 unknowns"). `isOneTwoOne` / `isOneTwoTwoOne`, a collinear run of plain clues with the value sequence whose HIDDEN neighbors all sit on ONE side of the clue line (the forcing "front"), consecutive clues overlapping, target in the front. The 1-3-1 corner is NOT collinear: `isOneThreeOneCorner` matches a 3 with two perpendicular orthogonal 1-neighbors (the L bend) whose five hidden squares partition into the two 1s' disjoint shared pairs plus the single square only the 3 sees; it is `kind`-aware (that lone square is the forced MINE, the two 1s' outer squares the forced SAFE). `isHole` / `isTriangle` (`matchesPocket`): a plain clue boxed to exactly k hidden cells (k=2 hole, k=3 triangle) whose EFFECTIVE value (face value minus adjacent KNOWN mines, flagged, revealed, or strike) is LESS THAN k, an AMBIGUOUS pocket: a mine is in there but you don't know which cell, and that ambiguity IS the hole/triangle, that is a SUBSET of a wider plain clue (≥4 hidden) of the SAME EFFECTIVE value sharing the whole pocket, so the wider clue's extra cells are SAFE. The `effective < k` test is LOAD-BEARING: effective == k means the pocket is ALL mines (unambiguous), a plain reduction, NOT a hole; that false match (using FACE value) shipped non-hole boards under the Holes lesson until 2026-06-15 (Christopher: "not all holes require a hole, are you sure you know what a hole is?"). The EFFECTIVE value is why TRIANGLES carry LARGER NUMBERS: a 3 next to a marked mine is effectively a 2 over a 3-cell pocket, still ambiguous (minesweeper.online's holes H1-H3 are all 1s; the triangle examples go to 2-3 with a marked mine). Holes are the '1-1' family by construction (equal effective value). The marked mine must be PRESENT (flagged/revealed) for the recognizer to count it, which is why `lessonRequiresShape` flags proven mines for the pocket family (see the gym section). `matchesOverlapPair` names the bare **1-1 / 1-2** by OVERLAP geometry (two plain clues sharing hidden squares; when `valBig - valSmall === |bigClue exclusive|`, the small clue's exclusive squares are all safe and the big clue's exclusive all mine, 1-1 is the equal-value subset case). 0-clues are excluded (a 0-clue is counting, not a pair) and it is **soundness-swept against ground truth** in `test/patternNames.test.mjs` (a named-safe square is never an actual mine, a named-mine square always is, across 150 full solves; the recognizer can even out-prove the frontier's gauss on big components, so the sweep checks ground truth, not frontier membership). This REPLACED the old source-based pair naming, which read the frontier's attributed sources and shadowed a 1-2's freed square to "1-1", so '1-2' never surfaced and the 1-2 lesson couldn't be required (it measured 0% required until this; see the gym section). The 1-2's requirable payload is its forced-SAFE square (the square only the 1 sees), NOT its mine, the gym never requires flagging, so a mine-find can't gate a lesson. `isTwoTwoTwoCorner` (gym-only, the hardest): a central plain 2 adjacent to the target whose other hidden cells split into two DISJOINT groups, each lower-bounded ≥1 by a flanking 2 (each flank's effective count minus the cells it sees outside the shared group), two disjoint ≥1 groups consume the central 2's whole count, freeing the cell only the central 2 sees; flags-blind (uses revealed/strike mines, the only knowns on a gym board). An incidental 1,2,1 digit run in open field (hidden on both sides) fails the one-side test and is never named, the **honesty contract** (a tier-2/3 region with no recognizable shape returns `region`, never a fabricated name). `isTwoTwoTwoCorner` is **soundness-swept** in `test/patternNames.test.mjs`: across generated boards it must NEVER name a cell the flags-blind solver can't independently prove safe. `hole` / `triangle` / `2-2-2` are **gym-only**, deliberately NOT in proofExplainer's `NAMED_SHAPES`, so a generic subset that isn't a visually-clean pocket can never make a receipt overclaim. Because the recognizers read HIDDEN neighbors, the caller must pass a state where the pattern's cells are still hidden. **Critical:** the gym classifies a move BEFORE it mutates the board, `_onCellClick` computes `moveName` before `_floodOpen` (flooding dissolves the front, so a post-reveal classify falls back from `1-2-1` to the bare pair `1-1`), and `_tryFlag` classifies before setting `isFlagged` (flagging removes the square from its clues' hidden sets, this is what lets the 1-3-1's forced-corner FLAG be named `1-3-1` rather than a bare tier-2 region). `_celebrate` cheers a named shape for a safe reveal OR a proven-mine flag (`PATTERN_SHAPE_NAMES`).
  - **Sound-proof substrate** (`src/logic/minimalProof.js` + `src/logic/proofClassify.js`, node-tested in `test/proofClassify.test.mjs`), the engine the rebuilt require-gate (and any future per-technique stat) rests on. `minimalProof.js` reads the constraint system `boardSolver.buildBoardConstraints` builds (refactored OUT of `findDeducibleFrontier` so both share one source of truth) and, for any deduced cell, finds its MINIMAL forcing clue-subset: SOUND (a subset that forces a cell forces it on the full board, by monotonicity, adding constraints only removes satisfying assignments) and COMPLETE (every deduction has one, else honest `region`); `subsetForces` is the soundness gate (the cited clues must force the square across every satisfying assignment). `proofClassify.js` names a cell FROM its proof: `classifyByProof` returns the RICHEST shape whose clues provably force it ("most specific wins", for player-facing technique stats), `simplestGatingRank` the CHEAPEST ("is anything simpler enough?", for the require-gate). Geometry (the `patternNames` recognizers, which now report their matched clues via an optional capture param) DESCRIBES a shape; `subsetForces` PROVES it, so a name can never overclaim on incidental geometry, the soundness flaw the old board-scan recognizers had no defense against. Swept against a brute-force oracle: 0 unsound names over ~14K classifications.
  - **Receipt naming**: `proofExplainer.explainDeduction` appends "That is the 1-2-1 pattern." to the tier-1/tier-2 sentence in the `full` style only, gated on `classifyPattern` returning a player-known shape, so the win-receipt confession, the daily crux teaser sentence, and post-loss copy all gain the honest name with zero extra wiring.
  - **Lesson-aware coaching** (`_celebrate`, keyed on the classifier name, not the tier): named shapes earn a cheer every time (the first per board includes a recognition tip from `PATTERN_COACH`); proven-mine flags get their reasoning once per board then a nod; the **Counting lesson frames every reveal as counting** (a tier-0 board is solved by flagging the forced mines and clearing what those numbers satisfy, the player's process IS counting, even where the flags-blind gate routes a square through a subset), with the flag-reduction beat ("flag it, and every number beside it now needs one fewer") taught on the first flag. `flag-reduction` is NOT a standalone lesson (it is literally Pass A, `remaining = expected - flagged`); it lives inside Counting. A bigger subset pair (a `pair` classification, e.g. 2-2 or 3-2) gets a `_nodPair` nod, "a 2-2 is a 1-1 wearing bigger numbers... what matters is that they match, not their size" (family-keyed on `classifyPattern`'s `family`), so the player learns to read past the larger digits and see the basic 1-1/1-2 underneath. Every performed technique is recorded to `gymTechniqueCounts` in `statsStorage.js` (local-only, `recordGymTechnique` / `getGymTechniqueCounts`; a disguised pair records under its family). All messages render on the `.lexicon-coach` line UNDER the board, updated in place.
